## What's wrong with the "33s" e2e_run_all.py

`e2e_run_all.py` runs **only YAML validation + workflow-exists check + 1
trivial goose call**. It is NOT real e2e coverage. A 33s run that
reports "179/179 PASS" tells you nothing about whether mas-engineer can
actually self-improve. The real proof needs a PTY-run with the
correct env vars (the example in this directory).

## Recipe-prompt bug discovered

The recipe's LLM prompt says literally:
`RECURSION-OVERRIDE-AWARE: env RECURSION_OVERRIDE=1 → APPLY-ONLY mode`

This makes the LLM conflate "RECURSION_OVERRIDE is set" with
"APPLY_ONLY mode" — it ignores the value `=2`. The fix is to either:
- (a) Use `{{ params.recursion_override }}` template + clearer mapping
- (b) Add explicit `RECURSION_OVERRIDE=2 → FULL_IMPROVEMENT` block

**Workaround in this run:** Set BOTH `MAS_TASK=FULL_IMPROVEMENT` env
AND `RECURSION_OVERRIDE=2` env — the LLM saw both in `env` output and
correctly chose FULL_IMPROVEMENT.
