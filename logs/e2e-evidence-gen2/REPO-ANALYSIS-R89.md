## 3. The Recipes — 119 sub_mas-*.yaml

### 3.1 Two Recipe-Patterns (Critical Distinction)

**Pattern A — Pure-LLM recipes (v1.0.0, ~80 of 119):**
- The recipe's `instructions:` block is the entire implementation
- The LLM reads them, follows step-by-step, uses `delegate()` to call other sub-recipes
- ~1200-2900 bytes typical
- Example: sub_mas-agent-guardian, sub_mas-config-auditor, sub_mas-goose-expert

**Pattern B — Thin-Wrapper recipes (v2.0.0, ~30+ of 119):**
- Recipe's `instructions:` block says "Call: `python3 tools/dev_*.py`"
- The real work is in a deterministic Python tool
- The LLM is just a router
- ~1100-2100 bytes
- Comment in YAML: `# R85 Phase N: thin wrapper — calls existing tools/dev_X.py`
- Examples: sub_mas-dashboard-data-reader, sub_mas-recovery-immune, sub_mas-im-session-reader

**Pattern A → Pattern B migration** is the core R85-R89 refactor strategy:
R85 replaced: 3 test-runner, 4 monitor, 4 dashboard, 5 tff, 4 security = 20 recipes
R88: same strategy
R89: +1 (recovery-immune, im-session-reader)
**Total thin-wrappers as of R89:** ~25-30 recipes
**Remaining pure-LLM:** ~85-90 recipes (next refactor target)

## 8. End-to-End: What Happens When You Run "goose" With mas-engineer Installed

1. **Goose loads** `.config/goose/recipes/dev-mas-engineer.yaml` (the main entry).
2. **dev-mas-engineer** is a thin delegator → delegates to `sub_mas-dev-director`.
3. **dev-director** does MODE-CHECK (R09), confirms with user (R01), then routes
   based on the user prompt's intention (parsed by `intention-parser`).
4. **Sub-Recipes** are called via `delegate()`. The called sub-recipe's
   `instructions:` block contains either:
   - **Pattern A (LLM):** Step-by-step procedure the LLM follows using shell/read/edit
   - **Pattern B (Thin):** "Call: `python3 tools/dev_X.py`" — deterministic
5. **Tools** are called as subprocess from the LLM's shell. The LLM parses JSON
   output and decides next step.
6. **Rules** are checked at every action via `dev_rule_checker.py --check R<NN>`.
   R01 (confirmation) blocks shell. R09 blocks cross-domain writes. R10 blocks
   unsaved YAML.
7. **Changes** are logged to `.state/changes.json` (38KB) and optionally committed
   via `git-operator` (R05).
8. **Signals** (yaml files in `.state/pipeline/signal_*done_*.yaml`) signal
   completion. R07 says "CP_DONE after Checkpoint".
