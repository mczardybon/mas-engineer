Build a complete Multi-Agent System called "customer-support" at
/tmp/customer-support, OPTIMIZE it via the mas-engineer E2E-improvement
loop, then ASSIGN 3 real support tickets to it. Repeat build-optimize-
tasks 5 times to measure consistency. Each cycle = fresh /tmp/customer-support.

This is the 2026-07-28 demo-team template: build → optimize → assign → repeat.
Mirrors the 2026-07-27 15x test methodology (run_15x_demo.py), but extended
with mandatory OPTIMIZE and TASK-ASSIGNMENT phases.

======================================================================
CYCLE 1 (FRESH) — BUILD + OPTIMIZE + ASSIGN
======================================================================

STEP 1 — Initialize the project skeleton
Run: python3 ~/.config/goose/recipes/tools/dev_generic_init.py
     --init /tmp/customer-support --components all

STEP 2 — Create 3 agents in /tmp/customer-support/recipe/sub/:

ARCHITECTURE: Linear pipeline (3 agents, sequential flow)

  user message
      |
      v
  intent-router        (classifies: billing|tech|general)
      |
      v
  specialist-handler   (handles the actual issue)
      |
      v
  empathic-responder   (adds empathy, formats final reply)

1. intent-router.yaml
   - Reads user message
   - Classifies into one of: "billing", "technical", "general"
   - Returns: {category: str, confidence: float, reasoning: str}
   - If confidence < 0.6, falls back to "general"

2. specialist-handler.yaml (sub_recipes based on category)
   - Receives {category, user_message}
   - Dispatches to the matching handler:
     * billing-handler: handles invoices, refunds, subscriptions
     * tech-handler: handles bugs, errors, integrations
     * general-handler: handles questions, feedback
   - Returns: {solution: str, steps: [str], needs_escalation: bool}

3. empathic-responder.yaml
   - Receives {user_message, solution, steps}
   - Adds empathy (acknowledges frustration if any)
   - Formats final reply as: greeting + empathy + solution + steps + offer
   - Returns: final customer-facing response string

STEP 3 — Create orchestrator root recipe /tmp/customer-support/recipe/
customer-support.yaml that references all 3 sub-recipes via sub_recipes.
The orchestrator runs them in strict sequence:
intent-router → specialist-handler → empathic-responder

STEP 4 — DASHBOARD SETUP (mandatory)
a) Set up MCP dashboard for the new project
b) First dashboard-data refresh
c) Verify dashboard:
   - "agents.total" = 3, "agents.healthy" = 3

   ['/tmp/customer-support/recipe/customer-support.yaml',

STEP 6 — Report (build only):

======================================================================
STEP 7 — OPTIMIZE via mas-engineer E2E-improvement (mandatory)
======================================================================

Run the mas-engineer improvement pipeline to harden the team:

a) SUB_MAS-GENERAL-IMPROVER on the team:
   goose run --recipe ~/.config/goose/recipes/mas-engineer/recipe/
   sub/sub_mas-general-improver.yaml --no-session --text
   "IMPROVE /tmp/customer-support — find and fix all YAML
   issues, missing fields, brittle patterns in the linear
   pipeline. Apply APPLY_ONLY mode (write fixes, do not invent
   new features)."

b) SUB_MAS-PRE-PUSH-VALIDATOR on the team:
   goose run --recipe ~/.config/goose/recipes/mas-engineer/recipe/
   sub/sub_mas-pre-push-validator.yaml --no-session --text
   "validate /tmp/customer-support — run all 14 checks.
   Pay special attention to the sequential pipeline integrity
   (intent-router MUST run before specialist-handler)."

c) DASHBOARD HEALTH CHECK:
   - python3 ~/.config/goose/recipes/tools/dev_dashboard_data.py
     /tmp/customer-support
   - cat /tmp/customer-support/.mas/dashboards/data.json | grep
     -E '"health"|"health_trend"|"issues"' -A 3

d) COUNT FIXES APPLIED:
   - before improvement: X issues (from validator report)
   - after improvement: Y issues (re-run validator)
   - delta = X - Y (must be > 0 for PASS)

STEP 7 — Report (optimize only):
- general-improver fixes applied: N (with file paths)
- pre-push-validator findings: before X, after Y, delta = X-Y
- dashboard health: before/after trend
- PASS criteria: delta > 0 AND no CRITICAL findings remaining

======================================================================
STEP 8 — ASSIGN 3 REAL SUPPORT TICKETS (mandatory)
======================================================================

After optimization, the team must solve 3 real support tickets
end-to-end. Each ticket = fresh `goose run --recipe customer-support.yaml
--text "<ticket>"`. Tickets must produce coherent, empathetic
customer-facing replies (not raw classifications).

TICKET 1 (BILLING — refund request):
  "Hi, I was charged $49.99 yesterday for a subscription I cancelled
  last week. Can you please refund this charge? Order #12345."
  - Expected: classify as billing, handle refund, empathetic reply
  - Quality gate: mentions refund, gives timeframe, asks for confirmation

TICKET 2 (TECHNICAL — integration bug):
  "Our API integration started returning 500 errors since yesterday.
  We use the python SDK v2.3. Nothing changed on our end. Please help."
  - Expected: classify as technical, suggest debugging steps
  - Quality gate: mentions error code, suggests check steps, escalates

TICKET 3 (GENERAL — feedback):
  "Just wanted to say I love the new dashboard design! The dark mode
  is exactly what I needed. Keep up the great work."
  - Expected: classify as general, warm acknowledgment
  - Quality gate: thanks user, mentions feedback channel, no upsell

For each ticket, run:
  goose run --recipe /tmp/customer-support/recipe/customer-support.yaml
  --no-session --text "<TICKET>"

Capture the full output. Verify:
- intent-router classification is correct
- specialist-handler produces actionable steps (not generic)
- empathic-responder output contains empathy marker ("I understand",
  "I apologize", "thank you for")
- No "as an AI" or "I cannot" hedging in the final reply
- Final reply is customer-facing (no internal YAML/JSON leakage)

STEP 8 — Report (tasks only):

| 1 | Refund $49.99  | billing/tech/general | Y/N | Y/N | PASS/FAIL |

PASS criteria: all 3 PASS (correct class + empathy + actionable) = CYCLE 1 PASS
