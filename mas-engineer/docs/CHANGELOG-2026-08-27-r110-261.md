## Library-bugs found (NOT fixed, tracked as R110-261a)

R110-261 reveals three small library-bugs the new tests don't claim to
fix (out of scope for a coverage sprint):

1. **dev_fast_scan.score math** — score=20 for 1 file with 2 passing
   conditions (the counter is per-condition, not per-file).
2. **dev_intention_parser.restrictions schema** — `requires_confirmation`
   only exists at `r["restrictions"][...]`, not at top-level (R110-261
   tests reach into restrictions; future callers might not).
3. **dev_category_drift commit-shape** — function takes `{hash, date,
   subject}`, but old docs say `{message, files}`. Tests use correct
   shape; docstring fix in R110-261a.

R110-261a will fix all three as a small library-bug sprint.
