## Problem

R110-261's coverage-sprint added 88 direct library-function tests for
10 `tools/dev_*.py` modules. Three of those tests revealed small
library-bugs in the tested code (documented in
`logs/e2e-evidence-gen2/R110-261-EVIDENCE.md` "Library-bugs found"
section). R110-261's commit body declared them "tracked as R110-261a"
and explicitly out of scope for a coverage sprint.

This R-Number is the follow-up fix.

## Changes

**Files modified (library code):**

- `tools/dev_fast_scan.py` — fixed `scan_settings` per-condition
  counter bug. Now: 1 perfect file → score 10.0 (was 20.0).
  1 half-good file → score 0.0 (was 10.0, misleading). 20 perfect
  files → score 10.0 (was 20.0, no longer uncapped). Findings per
  condition unchanged.
- `tools/dev_intention_parser.py` — `analyse_intention` now also
  exposes `requires_confirmation` at the top level of the result
  dict (alias for `result["restrictions"]["requires_confirmation"]`).
  The `restrictions[...]` location remains authoritative; the
  top-level alias is backward-compat for naive callers.

**Files added (regression tests):**

- `tests/test_r110261a_library_bug_fixes.py` (131 lines, 9 tests) —
  locks in both fixes. 5 tests for `dev_fast_scan.scan_settings`
  score math, 4 tests for `dev_intention_parser.analyse_intention`
  top-level alias. If a future commit breaks the post-fix behavior,
  these tests will fail and force a follow-up R-code.

**Investigation-only (no change):**

- `tools/dev_category_drift.py` — verified the source already
  documents the correct commit shape `{hash, date, subject}` in both
  the `run_git_log` function and the `classify_drift` docstring. The
  R110-261 round-3 test originally used a wrong fixture shape
  (`{message, files}`); that was corrected in the R110-261 test file
  itself, not in the library. No source change needed.

## Why R110-261a is a separate commit (not folded into R110-261)

1. **Commit hygiene** — R110-261 = test-only, R110-261a = test+source.
2. **Bisect-ability** — clean isolation if the fix breaks something.
3. **Pre-push-gate body-claim pattern (R110-78 / R110-258)** — splitting
   "tests reveal bug" from "tests pass after fix" tells a cleaner
   changelog story.
