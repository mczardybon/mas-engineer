**Bug 1 — [5/10] Doc links false-positives (4 files):**
The regex `r'\]\(([^)]+)\)'` matched Python raw-strings like
`r'''assert\s+["\'](\d+)\s+(\w[\w-]*)["\']\s+in\s+'''` because the
substring `](\d+)` was interpreted as a markdown link target. But
markdown's `[text](url)` syntax requires the `[` and `]` to wrap prose
link text, not be embedded inside a Python literal.

Affected files (all 4 had Python source containing `](X)` substrings):
- .mase/directives/R110-109-self-audit-spec-invariant.md
- .mase/directives/R110-118-self-audit-implementation.md
- .mase/directives/R110-78-spec-drift.md
- .mase/skills/devops/pre-push-gate/SKILL.md

**Fix 1:** New stricter regex
`\[([^\]\n\\"\'`]{2,}?)\]\(([^\)\n\\"\'`]+)\)` requires both [text] and
(url) to be ≥2 chars and to NOT contain Python-source-like chars
(backslash, quote, backtick). Plus extracted the entire check from
e2e-test.sh into a standalone `scripts/_check_doc_links.py` that
imports `scripts/_strip_code.py` (state-machine pass over markdown
text replacing fenced+inline code with spaces, newlines preserved).

**Bug 2 — [6/10] German-words (4 violations in 2 files):**
The language check (added in R110-228) had not been run end-to-end on
this branch's working tree. It found 4 german words across 2 files in
`recipe/` (specific german word list: see git history of those files
before commit ed890da, R110-253).

**Fix 2:** Replaced german words with their english equivalents (the
repo's source-of-truth language is English; the per-repo convention
R110-172+173 establishes this for the mas-engineer repo specifically).

**Refactor rationale:** The original e2e-test.sh [5/10] block was a
40-line inline python heredoc with 3 hardcoded scope values, no code
stripping, and a too-permissive regex. After this commit:
- `_strip_code.py` is a standalone, importable utility (state-machine
  pass, not regex) — reusable for future markdown scans
- `_check_doc_links.py` is the single source of truth for the doc-link
  check and reads `E2E_SCOPE` + `E2E_FILE_FILTER` from env (not from
  string interpolation in a bash heredoc, which was the source of the
  original backtick-in-bash-quoting trap)
- e2e-test.sh [5/10] block shrunk from ~40 lines to 7 lines
