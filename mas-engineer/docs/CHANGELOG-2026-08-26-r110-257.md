### `mas-engineer/tools/dev_evidence_sot.py` (NEW, 351 lines, PREVENTION layer 2)

Standalone SOT checker. 8 checks total:
- 4 working-tree checks: `evidence_sot_working_tree`, `directives_sot_working_tree`, `anti_sot_evidence_working_tree`, `anti_sot_directives_working_tree`
- 2 git-index checks: `evidence_sot_git_index`, `directives_sot_git_index`
- 2 dir-health checks: `sot_evidence_dir_health`, `sot_directives_dir_health`
- 1 optional: `--history` mode scans ALL commits via `git log --all` for past violators

Modes:
- `--strict` (default): exit 1 on any violation
- `--git`: includes git-index tracking (catches `git add`-staged violators)
- `--history`: scans full history (catches past violators that should have been retro-moved)
- `--json`: structured output for machine consumption

**Key design decision**: the tool scans for files at anti-SOT locations
even if they are `.gitignore`-excluded. Reason: `.gitignore` block is
defense-in-depth but invisible to `git status`; the tool must catch
in-the-act violations regardless of gitignore state.

## Root cause (8-R-number pattern)

Every SOT-violating file landed via "natural" session workflows:
- **Directives**: `dev_directive_applier.py` used to default to
  `mas-engineer/.directives/` (later changed to `.mase/directives/`
  per R110-115, but orphan files remained)
- **Evidence**: `logs/e2e-evidence-gen2/` was the ORIGINAL SOT
  (pre-R110-143, 2026-08-15). When R110-143 moved the SOT to
  REPO-ROOT, no bulk-move was done — files continued to accumulate
  at the old location over 7 R-numbers (R110-194 → R110-255)

R110-257 is the first commit that does BOTH the bulk cleanup AND
installs permanent prevention (3 layers + Check 24 in the gate).
