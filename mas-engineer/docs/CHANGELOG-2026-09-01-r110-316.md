## Bug

R110-315 (b1a16db) fixed the **single-source** problem:
`RECIPE_EXCLUDE` in `tests/test_unix_test_word.py` was missing the
new `sub_-.yaml` 0-byte test-side-effect fixture. R110-315 added
it to RECIPE_EXCLUDE and pytest turned green. But R110-316 noticed
that the e2e-runner (`tools/e2e_run_all.py::artifacts`) has a
PARALLEL list that was **NEVER in lockstep** with `RECIPE_EXCLUDE`.

Pre-R110-316, the 2 allowlist sources could silently disagree:
pytest tolerated a 0-byte fixture that e2e silently dropped
(or vice versa). No test caught this drift. R110-315 fixed the
symptom in one source but left the structural defect.

**Symptom:**

```text
# pre-R110-316: 2 allowlist sources, no enforcement
$ grep -E "RECIPE_EXCLUDE|artifacts" mas-engineer/tests/test_unix_test_word.py mas-engineer/tools/e2e_run_all.py
mas-engineer/tests/test_unix_test_word.py:
    RECIPE_EXCLUDE = {"sub_test-agent.yaml", "sub_-.yaml"}
mas-engineer/tools/e2e_run_all.py:
    artifacts = ["recipe/sub/sub_test-agent.yaml", ..., ]

# A new 0-byte fixture could be added to ONE source but not the other
# without ANY test catching the drift
```

## Root cause

The 2 allowlist sources were created in different sprints
(RECIPE_EXCLUDE in R110-34, e2e artifacts in R110-34) and
maintained independently. No test enforced the A ∪ B ⊇ C
invariant. The drift class is structurally identical to
the R110-78 commit-subject-regex 3-source drift, but
applied to a different concern (allowlist sources, not
validator regex sources).

## Fix

1. **Add the missing fixture to BOTH sources** in lockstep:
   - `tests/test_unix_test_word.py::RECIPE_EXCLUDE` already
     contains `sub_-.yaml` (R110-315)
   - `tools/e2e_run_all.py::artifacts` now also contains
     `recipe/sub/sub_-.yaml` (R110-316)
2. **Add a smoke test that enforces the 3-source lockstep**:
   `test_check_1_5_recipe_exclude_3_source_lockstep` in
   `tests/test_pre_push_check_1_5_skill_alignment.py` —
   asserts A ∪ B ⊇ C with explicit diagnostic naming
   A/B/C sets on failure
