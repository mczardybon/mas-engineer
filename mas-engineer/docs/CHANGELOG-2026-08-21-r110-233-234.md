### Root cause for defib block

```
bash: [325135: 1 (255)] tcsetattr: Inappropriate ioctl for device
```

Goose recipe engine's auto-repair (used by wf_recovery_defib) requires a
PTY for interactive LLM mode. Background terminal session is non-PTY
(`terminal(command=..., background=true, pty=false)`), so tcsetattr fails
on stdin/stdout. The 4 preceding recovery workflows used auto_repair too
but with simpler recipes that don't trigger the PTY codepath; defib's
recipe is more complex (full system state-restore + agent re-registration)
and needs the full interactive mode.

**`--no-interactive` flag clarification:** based on proc_6f2242cd2210
output (identical 132/132 PASS, same defib block, identical
`tcsetattr: Inappropriate ioctl for device` at line 14:19:05) the
flag does NOT skip the recovery-workflows' auto-repair codepath.
It only skips the `goose run --explain` interactive prompt that
would otherwise block the runner at TEST 5. Confirmed: 3 attempts
(proc_148587117a48 cwd-crash, proc_23f08e42022a default,
proc_6f2242cd2210 --no-interactive) all reach the same defib-block.
This is a deterministic environmental limit, not a flakiness.
