sweep: (a) zero test coverage of `tools/e2e_run_all.py` (the

## Why only 12% and not more?

`e2e_run_all.py` is structurally an E2E-runner. Its body consists
almost entirely of subprocess calls (`subprocess.run(goose …)`),
YAML loading, and reporting — all of which require either a live
goose CLI (~20 min real-time) or extensive monkeypatching to mock
out. The 9 tests added here cover the only pure-Python helpers in
the file (`log`, `section`, `find_all_recipes`, 2 module-level
constants). Closing the remaining ~88% gap is a separate sprint
that needs a goose-mock framework first.

## TEST-INTERACTION (cwd-polluter robustness, R110-589 follow-up)

The first commit of R110-589 (`3adf846`) failed full-sweep pytest
with **2 spurious failures** in `test_find_all_recipes_*` tests
caused by `tests/test_dev_dashboard_refresh_r110367.py` setting
`os.chdir("/")` in ~40 `finally` blocks. Because `find_all_recipes()`
uses `glob.glob("recipe/*.yaml")` (relative globs), those tests
saw `cwd=/` and returned `[]`.

Fix: an autouse `_restore_cwd_after_test` fixture in
`test_e2e_run_all_coverage.py` saves cwd on entry, `chdir`s to
`REPO_ROOT` for the test, and restores on exit. Verified:

- New tests alone: 9/9 PASS in 0.08s
- New tests + r110367 polluter (both orders): 53/53 PASS
- All 4 e2e-coverage test files together: 79/79 PASS

The r110367 test itself still pollutes cwd globally for any
CWD-relative test that runs after it — fixing the polluter is a
separate R-number (out of R110-589 scope).
