# R110-223 — Prevent wf_yaml_clone side-effect: auto-regenerates sub_mas-clone agent on every e2e run (DETECTION→CORRECTION→PREVENTION cycle)

## Context (the bug R110-222 just exposed, and R110-222 prematurely attempted to fix)

`recipe/sub/sub_mas-clone.yaml` is an auto-generated agent template (13945 bytes)
with placeholder task `"v1.0.0 | MAS-intern: list"` and no real prompt content
beyond the SOT-RULES preamble. The agent was **deleted in commit 60f1d01 (R19,
2026-07-23)** because it served no purpose.

Between 2026-08-14 and 2026-08-20, the same agent was **re-created 7 times** —
verified by 7 entries in `.mase/changes.json` with action=CREATE and
description "Neuer Agent: sub_mas-clone", each with a matching
`.mase/workflow_runs/wf_yaml_clone_<timestamp>.json` artifact.

Root cause (verified by `git show` + `grep` on 2026-08-20):
```
mas-engineer/tools/e2e_run_all.py:198
  "wf_yaml_clone": ["--task", "list", "--new_name", "clone", "--emoji", "🧪"]
        ↓
mas-engineer/tools/dev_template_generator.py:567
  _update_changes_json(base, "CREATE", f"Neuer Agent: sub_mas-{agent_key}")
        ↓
Writes 3 registry files (recipe/sub/sub_mas-<name>.yaml +
.mase/workflows.yaml SOT entry + recipe/dev-mas-engineer.yaml
sub_recipes entry) + 1 audit log entry (.mase/changes.json).
```

The e2e sample (`e2e_run_all.py`) calls `wf_yaml_clone` as part of its
task_workflow smoke test, which invokes the template generator with a
hard-coded `--new_name "clone"`. Every invocation of the e2e sample —
including CI runs, dev loop, and pre-push smoke tests — re-creates the
sub_mas-clone agent from scratch.

`tests/test_unix_test_word.py:RECIPE_EXCLUDE` already knew about this:
```python
RECIPE_EXCLUDE = {
    "sub_mas-clone.yaml",   # generated by wf_yaml_clone (template artifact)
    "sub_test-agent.yaml",  # auto-generated test artifact (0 bytes)
}
```
The orphan-detection test was **systematically blinded** instead of fixing the
upstream cause. Classic verification-theater pattern (R110-34 lesson).

R110-222 attempted a manual fix (file delete + SOT entry removal +
sub_recipes removal + changes.json history cleanup + guardian.yaml
drift cleanup + a new e2e skip-list entry for `wf_yaml_clone` + a new
regression test). This violated R110-204 / the mas-engineer-edit-rule
("Hermes NEVER writes mas-engineer files directly"). R110-223 must
revert R110-222 and produce a proper structural fix via the im-pipeline.

## Goal

Three layers, in order:

1. **DETECTION (verify it works)**: a pytest that fails if `sub_mas-clone`
   is registered in any of the 3 registry files OR if a new
   `CREATE: Neuer Agent: sub_mas-clone` entry appears in
   `.mase/changes.json` within 7 days. The test must run as part of
   the regular pytest suite (Check 17 of the pre-push-validator) so
   the regression is caught at pre-push time, not at a future e2e
   run.

2. **CORRECTION (im-pipeline produces)**: remove the
   sub_mas-clone.yaml file, the SOT entry in workflows.yaml, and
   the sub_recipes entry in dev-mas-engineer.yaml. Do this
   in a real goose session so the commit comes from the mas-engineer
   pipeline, not from Hermes (per R110-204 + im-pipeline skill rule
   "Hermes NEVER writes mas-engineer files directly").

3. **PREVENTION (the structural fix, this directive's primary goal)**:
   make `wf_yaml_clone` incapable of re-introducing sub_mas-clone
   on every e2e run. Three acceptable approaches (ranked):

   a. **Dry-run by default in e2e sample**: add a `--no-write`
      flag (or equivalent env var) to `dev_template_generator.py`
      that the e2e sample sets before calling wf_yaml_clone.
      Generator parses + validates the workflow but does not
      write any files. Best long-term — makes the generator
      sampleable for any future e2e tests.

   b. **Temp output dir in e2e sample**: change `e2e_run_all.py:198`
      to pass `--output-dir /tmp/e2e-yaml-clone` and have the
      generator honor that path instead of writing to the
      repo. Simpler to implement, but pollutes /tmp with
      agent files. Less clean than (a).

   c. **Wf_yaml_clone skip-list (last-resort fallback)**:
      add `wf_yaml_clone` to the e2e sample's
      SKIP_WORKFLOWS list. Stops the e2e loop from triggering
      the generator, but does NOT fix the underlying
      generator — a real user calling wf_yaml_clone would
      still regenerate sub_mas-clone. Use this only if (a)
      and (b) are too invasive for this sprint.

   The im-pipeline's general-improver should pick (a) if it can
   be done without breaking the e2e sample; otherwise (b); (c)
   is the minimum acceptable baseline.

   After CORRECTION, also clean up the historical CREATE
   entries in `.mase/changes.json` (keep entries older than
   7 days, but remove the recent ones if the file is small
   enough that the noise-to-signal ratio warrants it —
   decision is up to the im-pipeline designer).

## Required changes (3 files + 1 new tool + 1 new test)

### 1. `tools/dev_check_wf_yaml_clone_sideeffect.py` (NEW, ~60 lines)

Standalone Python script (no deps beyond stdlib + PyYAML), exit
0=clean / 1=sideeffect-detected. Mirrors the orphan-detection
pattern from R110-204's `dev_check_orphan_recipes.py` but for
the wf_yaml_clone-specific regression. Algorithm:

```
- load .mase/changes.json
- filter to entries with action=CREATE and description
  matching r"^Neuer Agent: sub_mas-(?!test-agent)"
  (note: sub_test-agent.yaml is a SEPARATE 0-byte auto-gen
  artifact that RECIPE_EXCLUDE handles; do not flag it)
- for each: parse timestamp; if within 7 days of now (UTC):
  emit a FAIL row with timestamp, description, workflow_run_file
- if any FAIL rows: print table + exit 1
- else: print "OK 0 sub_mas-clone re-registrations in last 7d" + exit 0
```

This is the **DETECTION** layer. It catches any future
re-registration in a 7-day window, which is enough to catch
the e2e-loop pattern (which fires within minutes of each
e2e run, not days later). For an even tighter check, add a
companion check: list the 3 registry files (recipe/sub/
sub_mas-clone.yaml, .mase/workflows.yaml SOT, recipe/dev-
mas-engineer.yaml sub_recipes) and fail if any of them
exists or contains sub_mas-clone.

Accept `--json` for CI / Check 17 consumption.

### 2. EXTRACT-FUNCTIONS / REGEX / PATTERNS

The exclusion regex (in both the tool and the test) MUST
match the agent-name list:
- `sub_mas-clone` (the bug)
- NOT `sub_test-agent` (separate, allowed 0-byte artifact)
- NOT `sub_mas-clone-of-<name>` if such a convention ever
  appears (deferred — currently does not exist)

Pattern: `^Neuer Agent: sub_mas-(?!test-agent|clone-of-)` —
flag anything that matches, allow the two named exceptions.

The 7-day window: `datetime.now(timezone.utc) -
timedelta(days=7)`. Window is intentional: the e2e loop
fires within seconds of each e2e run, not days later, so
7d catches the loop pattern with a wide safety margin while
not requiring historical changes.json cleanup.

### 7. RISK / SCOPE

- The im-pipeline's general-improver must be told to
  REVERT R110-222 first, then apply the structural fix.
  If it skips the revert and adds the structural fix on
  top of the R110-222 state, the workflow_runs will still
  show fresh CREATEs and the user-visible problem persists.
- The exclusion regex must be tested carefully: a typo
  in the negative-lookahead would either over-block
  (false positives for sub_test-agent) or under-block
  (false negative for sub_mas-clone). The 5-case pytest
  covers the boundaries.
- Option (a) `--no-write` requires a real generator
  change; if the im-pipeline designer picks (a) without
  testing it under the e2e sample, the e2e might fail
  because wf_yaml_clone exits non-zero. Mitigation:
  designer must run the e2e sample after the change,
  not just the new pytest test.
