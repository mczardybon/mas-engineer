Build a complete Multi-Agent System called "code-reviewer" at
/tmp/code-reviewer, OPTIMIZE it via the mas-engineer E2E-improvement
loop, then ASSIGN 3 real code-review jobs to it. Repeat build-optimize-
tasks 5 times to measure consistency. Each cycle = fresh /tmp/code-reviewer.

This is the 2026-07-28 demo-team template: build → optimize → assign → repeat.
Mirrors the 2026-07-27 15x test methodology (run_15x_demo.py), but extended
with mandatory OPTIMIZE and TASK-ASSIGNMENT phases.

======================================================================
CYCLE 1 (FRESH) — BUILD + OPTIMIZE + ASSIGN
======================================================================

STEP 1 — Initialize the project skeleton
Run: python3 ~/.config/goose/recipes/tools/dev_generic_init.py
     --init /tmp/code-reviewer --components all

STEP 2 — Create 4 parallel agents + 1 aggregator in
         /tmp/code-reviewer/recipe/sub/:

ARCHITECTURE: Parallel fan-out then aggregator (5 agents)

  code input
      |
      v
  review-orchestrator
      |
      +-- parallel start -----------------------+
      |                                         |
      +-> style-reviewer     (lint, formatting) |
      |                                         |
      +-> security-reviewer  (vulns, secrets)   |
      |                                         |
      +-> perf-reviewer      (perf, complexity) |
      |                                         |
      +-> test-reviewer      (coverage, edge)   |
      |                                         |
      parallel end (all 4 results) --------------+
      |
      v
  review-aggregator   (merges + prioritizes)
      |
      v
  final review report

1. style-reviewer.yaml
   - Reviews code for: lint errors, formatting, naming conventions,
     import order, dead code
   - Returns: {issues: [{file, line, severity, message, suggestion}]}

2. security-reviewer.yaml (MANDATORY — security gate)
   - Reviews code for: hardcoded secrets, SQL injection, XSS,
     insecure dependencies, missing auth checks
   - Returns: {issues: [{file, line, severity, cwe_id, fix}]}
   - This is a hard quality gate. Any HIGH severity issue
     blocks the merge.

3. perf-reviewer.yaml
   - Reviews code for: O(n^2) loops, blocking I/O, memory leaks,
     redundant computation, missing caching
   - Returns: {issues: [{file, line, severity, impact_ms, fix}]}

4. test-reviewer.yaml
   - Reviews code for: missing tests, edge cases, mock coverage,
     flaky patterns
   - Returns: {issues: [{file, line, severity, missing_scenarios}]}

5. review-aggregator.yaml
   - Receives {style_issues, security_issues, perf_issues, test_issues}
   - Merges into a single prioritized list (critical, high, medium, low)
   - Calculates overall score (0-100)
   - Decides: approve | request_changes | needs_discussion
   - Returns: {score, decision, summary, all_issues_sorted}

STEP 3 — Create orchestrator root recipe
/tmp/code-reviewer/recipe/code-reviewer.yaml that runs the 4 reviewers
in PARALLEL (no dependencies between them) and then dispatches to
review-aggregator. Document the parallel execution in instructions.

======================================================================
STEP 8 — ASSIGN 3 REAL CODE-REVIEW JOBS (mandatory)
======================================================================

After optimization, the team must review 3 real code snippets
end-to-end. Each snippet = fresh `goose run --recipe code-reviewer.yaml
--text "<snippet>"`. Reviews must produce prioritized issue lists,
not just "looks good" handwaving.

SNIPPET 1 (security — hardcoded secret):
  ```python
  import os
  def get_db():
      return psycopg2.connect(
          host="db.prod.example.com",
          user="admin",
          password="hunter2",  # hardcoded!
          dbname="app"
      )
  ```
  - Expected: security-reviewer flags CWE-798 (hardcoded credentials)
  - Quality gate: HIGH severity issue + fix suggestion

SNIPPET 2 (perf — O(n^2) loop):
  ```python
  def find_duplicates(items):
      dups = []
      for i, a in enumerate(items):
          for j, b in enumerate(items):
              if i != j and a == b and a not in dups:
                  dups.append(a)
      return dups
  ```
  - Expected: perf-reviewer flags O(n^2) + style-reviewer flags unused
    `j` variable + test-reviewer flags missing edge cases
  - Quality gate: ≥2 issues across reviewers, score < 80

SNIPPET 3 (style + test — unclean function):
  ```python
  def Calc(x,y):return x+y  # no spaces, bad name
  # No tests
  ```
  - Expected: style-reviewer flags naming + spacing
              test-reviewer flags "no tests for this function"
  - Quality gate: ≥2 issues, request_changes decision

For each snippet, run:
  goose run --recipe /tmp/code-reviewer/recipe/code-reviewer.yaml
  --no-session --text "<SNIPPET_PROMPT>"

Capture the full output. Verify:
- review-aggregator output contains numeric score (0-100)
- review-aggregator decision is one of: approve | request_changes |
  needs_discussion
- All HIGH severity issues have file:line + fix suggestion
- Issues are sorted by severity (critical/high/medium/low)
- No false-positive "I cannot review" hedging
